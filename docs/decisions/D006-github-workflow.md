# D006 — Seguimiento de trabajo y revisión en GitHub

Estado: aceptada.

Usar milestones e issues con criterios de cierre, ramas de trabajo y PRs antes
de integrar en main permite revisar alcance y validación. GitHub conserva el
estado de entrega; el repositorio conserva intención técnica y aprendizaje.
No se crean tareas de fases futuras. El coste es mantener ambas fuentes coherentes,
sin convertir los documentos en una réplica de issues y PRs.
